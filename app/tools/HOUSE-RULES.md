# กฎของบ้านนี้ (Frontend Factory House Rules)

เอกสารฉบับนี้รวบรวมกฎเฉพาะของโครงสร้าง Frontend Factory ในโปรเจกต์ Evarel อ่านจบใน 1 หน้า

---

## 1. กล่องต้องมี 3 ชั้นเสมอ (Three-Layer Box Pattern)
ทุกหน้าใน `app/pages/<box-name>/` ต้องประกอบด้วย 3 ชั้นหลัก:
- **ชั้น 1 (โครงหน้า)**: `<PascalName>Page.jsx` - ชิ้นส่วนประกอบโครงหน้า
- **ชั้น 2 (ชิ้นส่วนย่อย)**: โฟลเดอร์ `parts/` - ชิ้นส่วนเฉพาะของหน้านั้น
- **ชั้น 3 (ถาดข้อมูล & สไตล์เฉพาะหน้า)**: `<box-name>.tray.js` และ `<box-name>.style.css`

## 2. ห้ามดึงข้อมูลนอกถาด และห้ามใช้ `window` โดยตรง
- ข้อมูลและสถานะที่ไหลเข้ากล่องต้องผ่านถาดข้อมูล (`.tray.js`) เท่านั้น
- **ห้าม** อ่าน/เขียน `window.` โดยตรงในไฟล์ของกล่อง (ยกเว้นภายใน `.tray.js` ถ้าจำเป็น)
- **ห้าม** import ตรงข้ามกล่องจาก `app/pages/<box-a>` ไปยัง `app/pages/<box-b>` (หากต้องการใช้ร่วมกันให้ย้ายไป `app/shared/` หรือ `app/data/`)

## 3. ห้ามกล่องล้น (File Size & Line Limits)
- แต่ละไฟล์ในกล่องต้องอ่านจบได้ใน 1 นาที
- ขีดจำกัด: **ห้ามเกิน 300 บรรทัด** หรือ **ห้ามเกิน 15 KB** ต่อไฟล์
- หากเกิน ต้องแบ่งเป็นชิ้นส่วนย่อยใน `parts/`

## 4. ชื่อไฟล์และห้ามมีเลขเวอร์ชัน
- ชื่อโฟลเดอร์กล่องต้องเป็น lower-kebab-case (เช่น `user-profile`, `stats-view`)
- **ห้าม** ตั้งชื่อกล่องด้วยเลขเวอร์ชัน (เช่น `v1`, `v2`, `page2`, `stats_v3`)
- ชื่อไฟล์โครงหน้าต้องตรงตาม PascalCase (`UserProfilePage.jsx`)
- ชื่อไฟล์ถาดต้องลงท้ายด้วย `.tray.js`

## 5. บัตรประจำกล่องและแผ่นตรวจรับ (`BOX.md`)
- ทุกกล่องต้องมีไฟล์ `BOX.md` กำกับ
- ต้องมีส่วนสั้นสำหรับคนอ่าน + ส่วนกฎที่เครื่องอ่านได้ (JSON block) + แผ่นตรวจรับ (Acceptance Checklist)

## 6. สไตล์และการใช้แม่พิมพ์กลาง
- สไตล์กลาง สี ฟอนต์ ระยะห่าง ต้องอ้างอิงผ่านตัวแปร CSS จากแม่พิมพ์กลาง (`app/styles/MOLD-TABLE.md`)
- **ห้าม** เจียระไนสไตล์หน้างานด้วยค่าฝังตรง (hardcoded hex/px)
