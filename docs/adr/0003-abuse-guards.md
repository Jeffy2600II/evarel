# ADR 0003: ด่านกันคนหัวหมอ (เพดานข้อมูล + rate limit บัญชี)

สถานะ: ใช้งานแล้ว (11 ต.ค. 2026) ยกเว้นข้อที่ต้องให้เจ้าของโปรเจกต์ตั้งค่าใน Supabase (ดูท้ายเอกสาร)

## บริบท
แอปอาจเปิดสาธารณะ ผู้ใช้ไม่ใช่คนเดียวแล้ว และชั้นฟรี (Supabase 500MB, Workers CPU 10ms) ไม่มีที่ให้เสียเปล่า ตรวจโค้ดพบ: items ไม่มีเพดานขนาด (ส่ง subject 1MB ได้ 200), ไม่จำกัดจำนวน items, ทุกเส้นทางอ่าน body ทั้งก้อนก่อนตรวจ, ไม่มี rate limit ฝั่งบัญชี

## การตัดสินใจ
1. เพดานทุกตัวต้องสูงกว่าการใช้งานจริงของ UI หลายเท่า (ที่มา: MAX_REM=8, maxlength 12-80, คนจริงมี items สูงสุด 15) เพื่อไม่บล็อกคนจริง ค่าอยู่จุดเดียวใน `src/systems/items/validate.ts` (LIMITS)
2. ตัดขนาด body ก่อน parse: items/logs 64KB, AI 16KB, auth 2KB. ด่าน rate limit ต้องตัดก่อนอ่านเช่นกัน (พบจาก code review ว่าเคยเป็นช่องเอง)
3. rate limit บัญชีใช้ Postgres atomic (`rl_hit`) แบบ fixed window ไม่ใช้ Cloudflare Rate Limiting เพราะ: ตัวนับเป็นรายโลเคชันและ eventually consistent จึงไม่แม่นพอกันเดารหัส
4. คีย์เดารหัส = ไอพี + แฮชอีเมล (ไม่ใช่อีเมลล้วน) เพื่อไม่ให้คนหัวหมอล็อกบัญชีเหยื่อได้
5. ไอพีมาจาก `cf-connecting-ip` เท่านั้น ห้ามเชื่อ X-Forwarded-For. ส่งต่อให้ Supabase เป็น `Sb-Forwarded-For` เพื่อให้ rate limit ของ Supabase นับต่อผู้ใช้จริง ไม่ใช่รวมเป็นไอพีของ Worker
6. fail-open: ตัวนับล่ม/ยังไม่รัน migration = ปล่อยผ่าน (ไม่ให้คนจริงใช้ไม่ได้) แต่ต้องไม่ล้มเงียบ: `GET /api/health` รายงาน `rate_limit: active | inactive | unknown`
7. เก็บกวาด `rate_hits` แบบสุ่ม ~1/200 คำขอ ไม่เพิ่ม cron (ฟรีเทียร์ 5 ตัว)

## ทางเลือกที่ตัดทิ้ง
- Cloudflare Rate Limiting binding: ไม่แม่นพอ (ข้อ 3)
- ล็อกบัญชีหลังพลาดครั้งที่ N: เปิดช่องให้คนอื่นล็อกเหยื่อ (ข้อ 4)
- ตั้งเพดานตามค่าเฉลี่ยผู้ใช้: บล็อกคนจริงที่ใช้หนัก

## ข้อจำกัดที่ยอมรับ
- เพดาน 500 items/คนเป็นแบบนุ่ม (คำขอขนานที่ 499 เกินได้เล็กน้อย)
- เพดานจำนวนล็อกต่อ item ไม่ได้ตั้ง (1 แถวต่อวัน ประเมินความเสี่ยงต่ำ ยังไม่ยืนยันกับฐานจริง)
- ไอพีร่วมแบบ CGNAT: เพดานระดับไอพีตั้งหลวมไว้ (login 60/5 นาที)

## ต้องให้เจ้าของโปรเจกต์ทำ
1. รัน `supabase/migrations-003-rate-limit.sql` ใน SQL Editor (ก่อนรัน /api/health แสดง inactive และด่านเดารหัสไม่ทำงาน)
2. เปิด IP Address Forwarding: Authentication > Rate Limits (ก่อนเปิด Supabase นับทุกคนเป็นไอพีเดียวของ Worker)
