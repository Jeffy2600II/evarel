# ADR 0002: โควตา AI รายผู้ใช้

สถานะ: ตัดสินใจแล้ว (11 ต.ค. 2026)

## คำว่า "โควตา" แยกเป็น 3 อย่างที่ไม่ใช่สิ่งเดียวกัน
- โควตารายผู้ใช้ (ai_usage): เพดานต่อคนต่อวัน กันคนเดียวกินหมด
- เพดานรวม (global): กันผลรวมทุกคนเกินโควตา Groq ฟรี ซึ่งเป็นทรัพยากรร่วม
- โควตา Groq เอง: เป็นของผู้ให้บริการ ระบบแค่ป้องกันไม่ให้ชน และสลับ OpenRouter ได้

## ตัดสินใจ
- นับที่ Supabase แบบ atomic ไม่นับใน Worker เพราะหลาย isolate ทำงานพร้อมกัน ตัวนับในหน่วยความจำถูกหลบได้ด้วยการยิงขนาน
- หน่วยนับคือ ครั้งต่อวัน และ โทเคนต่อวัน (สองเพดานคู่กัน) วันนับตาม Asia/Bangkok
- LLM ล่มคืนโควตา 1 ครั้ง ผู้ใช้ไม่เสียสิทธิ์จากความผิดของระบบ
- ตัวเลขตั้งผ่านตัวแปร Worker (AI_DAILY_CALLS, AI_DAILY_TOKENS, AI_GLOBAL_CALLS) ปรับได้โดยไม่ต้อง deploy โค้ด
- ตัวนับล่มหรือยังไม่มีตาราง: ปล่อยผ่าน (fail-open) เพราะ AI พังทั้งระบบแย่กว่าโควตาหลวมชั่วคราว บันทึก log ทุกครั้ง

## ข้อจำกัดที่ยอมรับ
- สมัครบัญชีใหม่เพื่อเลี่ยงโควตาได้ เพราะ REQUIRE_EMAIL_VERIFICATION ปิดอยู่ (ตัดสินใจไว้แล้ว) ควรทบทวนเมื่อเปิดสาธารณะ

## ส่วนเพิ่ม 11 ต.ค. 2026: ให้ผู้ใช้เห็นโควตาของตัวเอง (evarel-quota-ui)
- GET /api/ai/quota: อ่านอย่างเดียว ไม่หัก ไม่เรียก LLM ตอบ { day, resetAt, blocked, reason?, calls, tokens } หรือ { unknown: true }
- อ่านตาราง ai_usage ด้วย JWT ของผู้ใช้ ให้ RLS กันข้ามผู้ใช้ หมายเหตุ: header apikey ยังเป็น SUPABASE_SERVICE_KEY เพราะ Worker ไม่มี anon key แต่ PostgREST ตัดสินสิทธิ์จาก Authorization พิสูจน์บนระบบจริงแล้ว (JWT ของ A อ่านแถวของ B ไม่ได้)
- ไม่แสดงโควตาส่วนกลางให้ผู้ใช้ (ตัวเลขของระบบ ไม่ใช่ของเขา)
- กันภาระ: จำกัดอัตราต่อผู้ใช้ + แคชสั้น 3 วินาที ปัจจุบันตัวจำกัดอัตรายังไม่ทำงานจริงจนกว่าจะรัน migration 003 (ดู /api/health ว่า rate_limit เป็น active) ภาระจึงคุมด้วยแคชเป็นหลัก
- ฝั่งแอป: ชิปโควตาเหนือช่องพิมพ์ + แผ่นรายละเอียด ล็อกช่องพิมพ์เมื่อหมด ปลดเองเมื่อถึงเวลารีเซ็ต อ่านไม่ได้ = ไม่ล็อก (fail-open) การล็อกฝั่งแอปเป็น UX เท่านั้น ด่านจริงคือ 429 ที่ Worker
- ตัดสินใจเบี่ยงจากสเปกเดิม 2 เรื่อง (ปฏิเสธได้): (1) ชิปอยู่เหนือช่องพิมพ์ ไม่ใช่ในแถบหัวหน้าแชท เพราะแถบหัวมีปุ่มอยู่แล้ว 3 ตัวบนจอแคบ (2) คงข้อความ 429 ในบับเบิลแชทไว้ เพราะเป็นบันทึกในประวัติแชท ส่วนชิปเป็นสถานะปัจจุบัน

- คอนทราสต์ตัวอักษรชิป >= 4.5:1 ทุกสถานะทั้งสองโหมด (วัดด้วย apca_contrast_checker และเทสต์เบราว์เซอร์จากสีที่คำนวณจริง) ใช้ token แยก --qc-warn/--qc-danger เฉพาะชิป ไม่แตะ --c-warn/--c-danger ที่ใช้ร่วม สีเดิมวัดได้ 2.39 / 3.43 / 3.87 ตกเกณฑ์
- ข้อสังเกตนอกขอบเขต: .ev-chip เดิมของแอปใช้คู่สีเดียวกันกับที่ตก จึงตกเช่นกัน ไม่แก้เพราะดีไซน์ล็อก รอ Master ตัดสิน
