# F4 ติดตรงไหน (บันทึกก่อนเริ่มกล่องนำร่อง)

ไฟล์เดียวสำหรับสิ่งที่เบ้าจูน เครื่องตรวจ หรือแม่พิมพ์ยังไม่พอ ต้องปรับเครื่องมือก่อนขยาย (F4 ผลลัพธ์ข้อ 4) แต่ละข้อมีหลักฐานที่รันซ้ำได้

## 1. กล่องลงทะเบียนหน้าตัวเองไม่ได้ ติดทั้งสองกล่องนำร่อง

- อาการ: `stats.jsx` และ `all.jsx` ปิดท้ายด้วย `window.EvarelPages = ...; window.EvarelPages.<ชื่อ> = ...; window.EvarelComponents.<ชื่อ> = ...` ซึ่งระบบเดิมต้องการ (รายการ `REACT_PAGES` ใน `19-views__settings`)
- กฎที่ชน: BOX-05 และ HOUSE-RULES ข้อ 2 ห้ามอ่านหรือเขียน `window.` ในไฟล์กล่องทุกกรณี ยกเว้น `.tray.js`
- หลักฐาน: สร้างกล่องด้วย `tuner.mjs` แล้วรัน `checker.mjs` ผ่าน (EXIT=0) จากนั้นเติมบรรทัด `window.EvarelPages.probe = ...` ลง `ProbePage.jsx` แล้วรันซ้ำ ตก `[BOX-05]` (EXIT=1)
- กล่องตัวอย่าง `example_box` ผ่านเพราะไม่มีการลงทะเบียนเลย จึงไม่เคยทดสอบเส้นทางนี้
- ทางแก้ที่ต้องเลือก (ยังไม่ทำ): ตัวหุ้มลงทะเบียนที่บิลด์สร้างให้ กล่องแค่ `export default` ส่วนบรรทัด `window.EvarelPages.*` ถูกต่อโดยบิลด์

## 2. ตัวบิลด์ไม่รู้จัก app/pages/

- `scripts/build-react.mjs` (66 บรรทัด) บิลด์เฉพาะ `app/src/react/*.jsx` เป็น `app/web/js/react/<ชื่อ>.js` ส่วน `app/pages/` มีแค่ `README.md`
- การแก้คือแตะท่อบิลด์ของทุกหน้า (16 หน้าใน `REACT_PAGES`) ความเสี่ยงสูงกว่าตัวงานย้ายสองหน้า ต้องมีตัวเทียบไบต์ก่อนหลังทุกหน้า

## 3. ขอบเขตที่นับ window ต่างกันสองแบบ

- ตัวนับ `w.<ชื่อ>` ที่ใช้ตลอด F3.3 วัดการอ่านข้ามกล่องผ่านตัวแปรช่วย เหลือ 0 แล้ว
- เครื่องตรวจจริงนับ `window.` ทุกจุดนอกถาด รวมบรรทัดลงทะเบียนและการรับ `window.EvarelReact` ที่หัวไฟล์ (`stats.jsx` และ `all.jsx` มีไฟล์ละ 3 บรรทัด) ทางแก้ต้องครอบทั้งการรับ React และการลงทะเบียน

## 4. หัวไฟล์รับ React ผ่าน window

- `const { h, Fragment } = window.EvarelReact;` ก็ชน BOX-05 เช่นกัน ต้องมีทางรับ `h`/`Fragment` ที่ไม่ใช่ `window.` (เช่น ผ่านถาด หรือบิลด์ฉีดให้)
- หลักฐาน: สร้างกล่อง `probeb` ด้วย `tuner.mjs` แล้วเติมบรรทัดนั้นไว้หัว `ProbebPage.jsx` รัน `checker.mjs` ตก `[BOX-05]` ส่วนกล่อง `probe` ที่ไม่มีบรรทัดนี้ผ่าน

## 5. ผลที่แก้แล้ว (ขั้น A, B, C) และข้อค้นพบใหม่จากการทำจริง

ข้อ 1, 2, 4 แก้ที่ท่อบิลด์: บิลด์ต่อบรรทัดรับ React และลงทะเบียนให้ กล่องไม่เขียน `window` (ดู [F4-build-pipeline-plan.md](F4-build-pipeline-plan.md)) ข้อ 3 ปิดเพราะกล่องผ่านเครื่องตรวจโดยไม่แตะเครื่องตรวจ

- **5.1 ไบต์ของไฟล์ผลบิลด์ไม่ตรงของเดิม (ตั้งใจยอมรับ):** minify ตั้งชื่อตัวแปรย่อใหม่ `stats.js` 5461 เป็น 5838 ไบต์ `all.js` 1910 เป็น 2045 ไบต์ Master ยอมใช้เกณฑ์ HTML ที่เรนเดอร์ตรงทุกไบต์แทน (28 ต.ค. 2026) หลักฐาน: `tests/stats_html_equiv.test.mjs` 6 กรณี ฉีดความผิดใน `AllRow.jsx` ตัวเทียบตก แล้วคืนกลับเป็น 0 ต่าง
- **5.2 เบ้าจูนติ๊กแผ่นตรวจรับล่วงหน้า (แก้แล้ว):** `BOX.md` ที่เบ้าจูนสร้างมีช่อง `[x]` ครบสามข้อทั้งที่ยังไม่ได้พิสูจน์อะไร และชี้ `parts/<Pascal>Part.jsx` ที่เป็นไฟล์ตัวอย่าง เครื่องตรวจเช็กแค่ว่ามีหัวข้อ ไม่เช็กว่าติ๊กจริงหรือบัตรตรงไฟล์ ผมแก้มือทั้งสองกล่อง แล้วแก้ที่ต้นเหตุ: เบ้าจูนสร้างช่องว่าง `[ ]` และเครื่องตรวจ parse JSON ของบัตรจริง ตรวจ `layers` ชี้ไฟล์ที่มี, ไฟล์ใน `parts/` ทุกไฟล์ถูกประกาศ (ไม่มีไฟล์แอบ), `register` รูปถูก หลักฐาน: ฉีดความผิด 4 แบบกับบัตรจริงของ `stats` ตก BOX-02 ทั้งหมด คืนแล้วผ่าน และ `example_box` ที่ `parts` เป็นสตริงยังผ่าน
- **5.3 หน้าใหม่จากเบ้าจูนยังไม่โผล่ในแอป (แก้แล้ว):** ทดลองสร้างหน้า `newpage` ในสำเนาชั่วคราว 3 คำสั่ง (`tuner`, `build-react`, `checker`) ผ่านหมด แต่ยังต้องแก้มืออีก 3 จุด คือรายการ `REACT_PAGES` ใน `app/src/m/19-views__settings.ts` รายการแคชใน `app/web/sw.js` และจุดเรียก `EvarelPages.<ชื่อ>` ใน `VIEWS` เอกสาร F4 สั่งว่าเบ้าจูนต้องทำสามจุดนี้เอง ตอนนี้ยังไม่ทำ `stats` และ `all` ผ่านเพราะสองชื่อนี้อยู่ในสามจุดนั้นอยู่แล้ว จึงไม่ได้พิสูจน์ว่าเบ้าจูนทำให้
  - **ผลหลังแก้:** สร้างกล่อง `fresh`, `multi`, `newpage` ด้วยเบ้าจูนในสำเนา รัน `build-react.mjs` ครั้งเดียว บิลด์เติม `REACT_BOX_PAGES` ใน `19-views__settings.ts` (และผลคอมไพล์ `.js` คู่กัน) กับรายการแคชใน `sw.js` เอง เปิดหน้าแอปจริง ไฟล์กล่องทั้งสามถูกโหลดเอง (HTTP 200) และ `EvarelPages`/`EvarelComponents` มีชื่อใหม่ครบ โดยไม่แก้มือสักจุด `pageerror` เท่าฐานเดิมที่ไม่มีกล่องทดสอบ (5 ข้อความเดิมเพราะไม่มี API)
  - **จุดที่ 3 (`VIEWS.<ชื่อ>`) ไม่ได้ทำอัตโนมัติ และตั้งใจไม่ทำ:** `VIEWS` เรียกใช้เฉพาะ 4 แท็บ (today, calendar, stats, all) ตรรกะแต่ละแท็บเป็นของเฉพาะหน้า (หัวข้อ ตัวกรอง fallback การแปลง chevron) ส่วน 12 หน้าที่เหลือไม่ผ่าน `VIEWS` เลย จึงให้บิลด์ลงทะเบียน `EvarelPages`/`EvarelComponents` ซึ่งเป็นทางเข้าที่ทุกหน้าใช้จริง ให้เบ้าจูนเดาโค้ด `VIEWS` ให้จะเสี่ยงทำหน้าตาเพี้ยน

- **5.4 เอกสาร F4 สมมติผิดว่า `all` ใช้ `item-row` ร่วมกับ `today`:** ตรวจ `all.jsx` แล้วไม่มีการอ้าง `item-row` เลย จึงไม่มีชิ้นส่วนกลางให้ลองผ่าน `shared/` ความเสี่ยงที่เอกสารตั้งไว้ ("หน้านำร่องง่ายเกินไป") ยังไม่ถูกลดตามที่วางแผน
- **5.5 สไตล์ของกล่องยังไม่มีทางเข้าแอป:** `stats.style.css` และ `all.style.css` เป็นโครงว่าง `scripts/build-css.mjs` ไม่รวมไฟล์ `.style.css` ของกล่อง (ขั้น D ของแผนท่อบิลด์ ยังไม่ทำ)
- **5.6 ตัวเลขกล่องล้นจากสองหน้านำร่องบอกอะไรไม่ได้:** ไฟล์ใหญ่สุด 24 บรรทัด 1,511 ไบต์ ห่างเกณฑ์ 300 บรรทัด และ 15 KB เกิน 10 เท่า สองกล่องมี 8 และ 6 ไฟล์ (stats: หน้า, ถาด, สไตล์, บัตร, parts 4) (all: หน้า, ถาด, สไตล์, บัตร, parts 2) ต้องรอหน้าใหญ่ (today, form) ก่อนตัดสินเกณฑ์

- **5.7 หน้า React ที่เหลือ 12 หน้าไม่ใช่ "หนึ่งไฟล์ หนึ่งชื่อ":** วัดจากซอร์สปัจจุบัน ทุกหน้า (ยกเว้น `item-row`) ลงทะเบียนทั้ง `EvarelPages` และ `EvarelComponents`, `dialog` ลง 2 ชื่อ (`dialogCard`, `confirmCard`), `form` ลง 2 ชื่อ (`typeBody`, `formBody`), `item-row` ลงเฉพาะ `EvarelComponents.itemRow` ท่อบิลด์ขั้น A-B รองรับแค่ชื่อเดียวต่อกล่อง จึงขยายด้วยมานิเฟสต์ `register` ในบัตร (`pages[]`, `components[]`, `after[]`) ผลทดสอบ: กล่อง `multi` ลง 2 หน้า + 1 component เรนเดอร์ถูกต้องในเบราว์เซอร์จริง
- **5.8 `detail` และ `sheet` มี wrapper หลายบรรทัดของตัวเอง (ยังไม่ครอบ):** ทั้งสองลงทะเบียนด้วยฟังก์ชัน `(p) => { ... }` ที่ทำมากกว่าเรนเดอร์หนึ่งบรรทัด มานิเฟสต์รองรับเฉพาะรูป `renderToStaticMarkup(h(X, prepare(raw)))` ต้องย้ายตรรกะ wrapper เข้าถาด (`prepare`) ตอนย้ายสองหน้านี้ ซึ่งเป็นงานต่อหน้า
- **5.9 ลำดับโหลดมีความหมาย:** `today` ใช้ `EvarelComponents.itemRow` ตอนโหลด จึงต้องมาหลัง `item-row` (เทสต์ `today_equiv` ยืนยัน) บิลด์จึงคงลำดับ 16 หน้าเดิมเป๊ะ (`REACT_PAGES_BASE`) กล่องใหม่ต่อท้ายตามชื่อ และมี `after` บังคับลำดับ `after` ที่ชี้ชื่อผีหรือเป็นวงวนล้มบิลด์พร้อมเหตุผล เมื่อกล่องเดิมถูกย้ายเข้ากล่อง (เช่น `item-row`, `today`) ต้องคงชื่อไว้ใน `REACT_PAGES_BASE` ด้วย ไม่งั้นบิลด์ไม่ใส่ซ้ำในบล็อก และลำดับเดิมไม่เปลี่ยน
- **5.10 `build-next.mjs` เจน `sw.js` ของเส้นทาง Next เอง:** แทนทั้งก้อน `const CORE = [...]` ด้วยรายการจากไฟล์จริงใน `out/` บล็อกกล่องใน `sw.js` จึงมีผลกับเส้นทาง `app/web` เดิมเท่านั้น เส้นทาง Next แคชกล่องตามไฟล์จริงอยู่แล้ว (ไม่ได้ทดสอบ build Next ในรอบนี้)
- **5.11 ข้อผิดพลาดของตัวบิลด์เองที่เจอและแก้ระหว่างทำ (บันทึกไว้เป็นบทเรียนของกลไก):** (ก) แรกใส่ชื่อที่ลงทะเบียน (`multiA`) ลงรายการโหลดแทนชื่อไฟล์ (`multi`) ทำให้ `sw.js` แคชไฟล์ที่ไม่มีและ `addAll` ล้มทั้งแอป จับได้ด้วยข้อทดสอบ "ทุกไฟล์ใน CORE มีจริง" (ข) แรกใส่ `stats`/`all` ซ้ำในบล็อกทั้งที่อยู่ใน BASE แล้ว (ค) ตัวอ่าน prepare ด้วย regex เปราะ เปลี่ยนไปอ่าน export จริงด้วย esbuild metafile

- **5.12 `build-css` สร้างคลาสขยะจากข้อความ error ใน `auth.tray.js`:** ข้อความ `'[tray:auth] ...'` ถูก Tailwind อ่านเป็นคลาส arbitrary แล้วเติม `.[tray:auth]{tray:auth;}` ลง `app.css` ทุกครั้งที่รันบิลด์เว็บเต็ม (`build-web.mjs`) เป็นของเดิมก่อนงานนี้ ไม่กระทบหน้าตา ผมย้อนไฟล์ก่อน commit ข้อเสนอ: เปลี่ยนรูปข้อความ error ในถาดทุกไฟล์ไม่ให้ขึ้นต้นด้วย `[` หรือเพิ่มไฟล์ถาดเข้า ignore ของ Tailwind (ยังไม่ทำ รอ Master)

## สถานะ ณ commit ที่บันทึก

- กล่อง `stats` และ `all` อยู่ใน `app/pages/` ผ่านเครื่องตรวจ ประตูภาพ 30/30 ที่ 0 พิกเซล errs app 0 ตัวเทียบ HTML 6 กรณีตรงทุกไบต์ ซอร์สเดิมใน `app/src/react/` ลบแล้ว (ไม่ค้างสองชุด)
- เบ้าจูนลงทะเบียนเอง (รายการหน้า, แคช sw.js, ทั้ง `EvarelPages` และ `EvarelComponents`) ใช้งานได้แล้ว ยกเว้น wrapper เฉพาะหน้าแบบ `detail`/`sheet` (ข้อ 5.8)
- ยังไม่ปล่อย sub-agent เพราะ F4 ต้องตรวจภาพ 0 พิกเซลด้วยเบราว์เซอร์ในเครื่อง
