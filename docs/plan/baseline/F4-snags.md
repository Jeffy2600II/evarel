# F4 ติดตรงไหน (บันทึกก่อนเริ่มกล่องนำร่อง)

ไฟล์เดียวสำหรับสิ่งที่เบ้าจูน เครื่องตรวจ หรือแม่พิมพ์ยังไม่พอ ต้องปรับเครื่องมือก่อนขยาย (F4 ผลลัพธ์ข้อ 4) แต่ละข้อมีหลักฐานที่รันซ้ำได้

## 1. กล่องลงทะเบียนหน้าตัวเองไม่ได้ ติดทั้งสองกล่องนำร่อง

- อาการ: `stats.jsx` และ `all.jsx` ปิดท้ายด้วย `window.EvarelPages = ...; window.EvarelPages.<ชื่อ> = ...; window.EvarelComponents.<ชื่อ> = ...` ซึ่งระบบเดิมต้องการ (รายการ `REACT_PAGES` ใน `19-views__settings`)
- กฎที่ชน: BOX-05 และ HOUSE-RULES ข้อ 2 ห้ามอ่านหรือเขียน `window.` ในไฟล์กล่องทุกกรณี ยกเว้น `.tray.js`
- หลักฐาน: สร้างกล่องด้วย `tuner.mjs` แล้วรัน `checker.mjs` ผ่าน (EXIT=0) จากนั้นเติมบรรทัด `window.EvarelPages.probe = ...` ลง `ProbePage.jsx` แล้วรันซ้ำ ตก `[BOX-05]` (EXIT=1)
- กล่องตัวอย่าง `example_box` ผ่านเพราะไม่มีการลงทะเบียนเลย จึงไม่เคยทดสอบเส้นทางนี้
- ทางแก้ที่ต้องเลือก (ยังไม่ทำ): ตัวหุ้มลงทะเบียนที่บิลด์สร้างให้ กล่องแค่ `export default` ส่วนบรรทัด `window.EvarelPages.*` ถูกต่อโดยบิลด์

## 2. ตัวบิลด์ไม่รู้จัก app/pages/

- `scripts/build-react.mjs` (66 บรรทัด) บิลด์เฉพาะ `app/src/react/*.jsx` เป็น `app/web/js/react/<ชื่อ>.js` ส่วน `app/pages/` มีแค่ `README.md`
- การแก้คือแตะท่อบิลด์ของทุกหน้า (16 หน้าใน `REACT_PAGES`) ความเสี่ยงสูงกว่าตัวงานย้ายสองหน้า ต้องมีตัวเทียบไบต์ก่อนหลังทุกหน้า

## 3. ขอบเขตที่นับ window ต่างกันสองแบบ

- ตัวนับ `w.<ชื่อ>` ที่ใช้ตลอด F3.3 วัดการอ่านข้ามกล่องผ่านตัวแปรช่วย เหลือ 0 แล้ว
- เครื่องตรวจจริงนับ `window.` ทุกจุดนอกถาด รวมบรรทัดลงทะเบียนและการรับ `window.EvarelReact` ที่หัวไฟล์ (`stats.jsx` และ `all.jsx` มีไฟล์ละ 3 บรรทัด) ทางแก้ต้องครอบทั้งการรับ React และการลงทะเบียน

## 4. หัวไฟล์รับ React ผ่าน window

- `const { h, Fragment } = window.EvarelReact;` ก็ชน BOX-05 เช่นกัน ต้องมีทางรับ `h`/`Fragment` ที่ไม่ใช่ `window.` (เช่น ผ่านถาด หรือบิลด์ฉีดให้)
- หลักฐาน: สร้างกล่อง `probeb` ด้วย `tuner.mjs` แล้วเติมบรรทัดนั้นไว้หัว `ProbebPage.jsx` รัน `checker.mjs` ตก `[BOX-05]` ส่วนกล่อง `probe` ที่ไม่มีบรรทัดนี้ผ่าน

## 5. ผลที่แก้แล้ว (ขั้น A, B, C) และข้อค้นพบใหม่จากการทำจริง

ข้อ 1, 2, 4 แก้ที่ท่อบิลด์: บิลด์ต่อบรรทัดรับ React และลงทะเบียนให้ กล่องไม่เขียน `window` (ดู [F4-build-pipeline-plan.md](F4-build-pipeline-plan.md)) ข้อ 3 ปิดเพราะกล่องผ่านเครื่องตรวจโดยไม่แตะเครื่องตรวจ

- **5.1 ไบต์ของไฟล์ผลบิลด์ไม่ตรงของเดิม (ตั้งใจยอมรับ):** minify ตั้งชื่อตัวแปรย่อใหม่ `stats.js` 5461 เป็น 5838 ไบต์ `all.js` 1910 เป็น 2045 ไบต์ Master ยอมใช้เกณฑ์ HTML ที่เรนเดอร์ตรงทุกไบต์แทน (28 ต.ค. 2026) หลักฐาน: `tests/stats_html_equiv.test.mjs` 6 กรณี ฉีดความผิดใน `AllRow.jsx` ตัวเทียบตก แล้วคืนกลับเป็น 0 ต่าง
- **5.2 เบ้าจูนติ๊กแผ่นตรวจรับล่วงหน้า:** `BOX.md` ที่เบ้าจูนสร้างมีช่อง `[x]` ครบสามข้อทั้งที่ยังไม่ได้พิสูจน์อะไร และชี้ `parts/<Pascal>Part.jsx` ที่เป็นไฟล์ตัวอย่าง เครื่องตรวจเช็กแค่ว่ามีหัวข้อ ไม่เช็กว่าติ๊กจริงหรือบัตรตรงไฟล์ ผมแก้มือทั้งสองกล่อง เสนอให้เบ้าจูนสร้างช่องว่าง `[ ]` และให้เครื่องตรวจเทียบ `layers.parts` กับไฟล์จริง
- **5.3 หน้าใหม่จากเบ้าจูนยังไม่โผล่ในแอป (ผลลัพธ์ข้อ 6 ยังไม่ผ่านตามเอกสาร):** ทดลองสร้างหน้า `newpage` ในสำเนาชั่วคราว 3 คำสั่ง (`tuner`, `build-react`, `checker`) ผ่านหมด แต่ยังต้องแก้มืออีก 3 จุด คือรายการ `REACT_PAGES` ใน `app/src/m/19-views__settings.ts` รายการแคชใน `app/web/sw.js` และจุดเรียก `EvarelPages.<ชื่อ>` ใน `VIEWS` เอกสาร F4 สั่งว่าเบ้าจูนต้องทำสามจุดนี้เอง ตอนนี้ยังไม่ทำ `stats` และ `all` ผ่านเพราะสองชื่อนี้อยู่ในสามจุดนั้นอยู่แล้ว จึงไม่ได้พิสูจน์ว่าเบ้าจูนทำให้
- **5.4 เอกสาร F4 สมมติผิดว่า `all` ใช้ `item-row` ร่วมกับ `today`:** ตรวจ `all.jsx` แล้วไม่มีการอ้าง `item-row` เลย จึงไม่มีชิ้นส่วนกลางให้ลองผ่าน `shared/` ความเสี่ยงที่เอกสารตั้งไว้ ("หน้านำร่องง่ายเกินไป") ยังไม่ถูกลดตามที่วางแผน
- **5.5 สไตล์ของกล่องยังไม่มีทางเข้าแอป:** `stats.style.css` และ `all.style.css` เป็นโครงว่าง `scripts/build-css.mjs` ไม่รวมไฟล์ `.style.css` ของกล่อง (ขั้น D ของแผนท่อบิลด์ ยังไม่ทำ)
- **5.6 ตัวเลขกล่องล้นจากสองหน้านำร่องบอกอะไรไม่ได้:** ไฟล์ใหญ่สุด 24 บรรทัด 1,511 ไบต์ ห่างเกณฑ์ 300 บรรทัด และ 15 KB เกิน 10 เท่า สองกล่องมี 8 และ 6 ไฟล์ (stats: หน้า, ถาด, สไตล์, บัตร, parts 4) (all: หน้า, ถาด, สไตล์, บัตร, parts 2) ต้องรอหน้าใหญ่ (today, form) ก่อนตัดสินเกณฑ์
