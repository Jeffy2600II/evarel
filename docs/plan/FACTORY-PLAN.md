# แผนเสริม: โรงงาน Frontend ของ Evarel

กฎของไฟล์นี้เหมือนแผนหลัก: ห้ามมีวิธีทำ ห้ามมีโค้ด ห้ามมีค่าตั้งค่า มีเพียง ขั้น เป้าหมาย ผลลัพธ์ที่ตรวจได้ สถานะ และลิงก์ไปไฟล์ลึก
แผนนี้เป็นแผนเสริมของ [MASTER-PLAN.md](MASTER-PLAN.md): เป็นงานเพิ่มเติมที่ไม่มีในแผนเดิม แผนเดิมทุกขั้นยังเหมือนเดิมทุกประการ
ทำบนสาขา develop
ที่มา: เอกสารรวมโรงงาน Frontend Evarel ที่ Master ส่งมา (แนวคิด 9 หัวข้อ B1 ถึง B9) ทุกชื่อโฟลเดอร์ ชื่อไฟล์ และลำดับในแผนนี้เอามาจากเอกสารนั้นตรงตัว

## 1. หลักของแผนนี้

**ทำตามแนวคิดโรงงานเป๊ะ ทั้งโครงสร้างและกลไก ไม่ตีความ ไม่ลดรูป ไม่ผสมกับโครงเดิม** เอกสารออกแบบมาเพื่อระบบ Evarel โดยเฉพาะ และ Master ตกลงแล้วว่าเป็นข้อสรุปจบ
สิ่งเดียวที่ไม่เปลี่ยน: **ผู้ใช้เห็นหน้าตาทุกหน้าเหมือนเดิม** ทุกอย่างเบื้องหลังเปลี่ยนตามแนวคิดใหม่

เป้าหมายตามเอกสาร: พัฒนาง่าย เร็ว เป็นระบบ คาดเดาได้ ทั้ง agent และนักพัฒนามนุษย์ที่ถูกจ้างมา ดีกว่าระบบเดิม

ลำดับแนวคิดที่ Master ยึด: กล่องฟีเจอร์ (ข้อ 1) > โกดังแบ่งโซน (ข้อ 2) > แม่พิมพ์กลาง (ข้อ 3) > รับส่งผ่านถาด (ข้อ 4)

## 2. โครงสร้างปลายทาง (ตามเอกสาร B1 และ B4 ตรงตัว)

```
app/
├─ pages/
│  ├─ <ชื่อหน้า>/          หน้าหนึ่ง = กล่องหนึ่ง
│  │  ├─ <ชื่อหน้า>Page    โครงหน้า (ประกอบจากชิ้นส่วน)
│  │  ├─ parts/            ชิ้นส่วนเฉพาะของหน้านั้น
│  │  ├─ <ชื่อหน้า>.tray   ถาดข้อมูลของหน้านั้น
│  │  └─ <ชื่อหน้า>.style  สีเฉพาะหน้า (มีหรือไม่ก็ได้)
├─ shared/                 ปุ่ม กล่อง ไอคอน ใช้ร่วมทุกหน้า
├─ styles/                 แม่พิมพ์กลาง: สี ฟอนต์ ระยะห่าง
├─ data/                   ถาดข้อมูล แยกตามโมดูล
└─ tools/                  เบ้าจูน เครื่องตรวจ ตัววาดแผนที่
```

| โซน | หน้าที่ (ตามเอกสาร B1) |
|---|---|
| `pages/` | หน้าหนึ่ง = กล่องหนึ่ง เพิ่มหน้า = วางกล่องใหม่ ถอนหน้า = ยกกล่องทิ้ง ไม่มีเศษหล่น |
| `shared/` | ปุ่ม กล่อง ไอคอนที่ใช้ร่วมหลายหน้า แก้จุดเดียว ทุกหน้าเปลี่ยนพร้อมกัน |
| `styles/` | สี ฟอนต์ ระยะห่าง ขนาด ปุ่มมาตรฐาน มาจากตารางจุดเดียว เปลี่ยนฟอนต์ทั้งเว็บ = แก้บรรทัดเดียว |
| `data/` | ถาดรับข้อมูลกำหนดรูปชัด หน้าจอไม่ดึงของเอง ข้อมูลพัง = รู้ทันทีว่าตู้ไหน |
| `tools/` | เบ้าจูน เครื่องตรวจ ตัววาดแผนที่ |

กล่องทุกใบจัดเหมือนกันเป๊ะ สามชั้น (B2): ชั้น 1 โครงหน้า, ชั้น 2 `parts/`, ชั้น 3 ถาดข้อมูล `.tray` สีเฉพาะหน้า `.style` มีหรือไม่มีก็ได้

## 6. กติกาคุมความง่าย (B6 ตรงตัว บังคับด้วยเครื่องตรวจ ไม่ใช่ความจำ)

1. ไฟล์หนึ่งทำหน้าที่เดียว อ่านจบในนาที
2. กล่องล้น = แบ่งกล่องย่อย ห้ามยัดจนล้น
3. ข้อมูลไหลทางเดียว รับ → ปรุง → เสิร์ฟ ทุกหน้าเหมือนกัน
4. แผนที่วาดจากโค้ดจริงเสมอ ไม่เขียนมือ
5. สไตล์พิเศษห้ามเจียระไนหน้างาน ต้องขึ้นแม่พิมพ์กลางก่อน
6. หน้าใหม่เกิดในโครงใหม่ หน้าเก่าย้ายทีละกล่อง ไม่รื้อวันเดียว

ไม่ผ่านกติกา = ไม่ปล่อย (เอกสาร B5 ข้อ 2) ตัวตรวจบอกว่าผิดข้อไหนเพราะอะไร (เอกสารข้อ C)

### การวัดคะแนน (เอกสาร B9)
เอกสารให้คะแนนเต็ม 60 (6 ด้าน ด้านละ 10): สูตรโกดัง กล่อง แม่พิมพ์ ได้ 52 และเมื่อบวกอัปเกรด 4 ข้อ (แผนที่ เบ้าจูน กฎขนาด ทางเดียว) ได้ 58.8 เอกสารระบุเองว่าเป็นคะแนนจากหลักการ ยังไม่เทียบโค้ดจริง โดยเฉพาะด้านย้ายจากของเดิม (8/10) และถอนเลข 56.8 กับ 57.5 ทิ้งเพราะไม่มีหลักฐาน แผนนี้จึงประเมินคะแนนใหม่จากโค้ดจริงหลัง F4 และหลัง F6 ด้วยเกณฑ์ที่วัดได้ (ข้อ 7) ไม่ใช้เลข 52 และ 58.8 เป็นเป้า

**ผลการประเมินหลัง F6 (จากโค้ดจริง):** [บัตรคะแนนโรงงาน](../assessment/FACTORY-SCORECARD.md) · 10 ด้าน ถ่วงน้ำหนัก รวม **92.6/100** วัด ณ commit `4ea6d2d` (รุ่น 2026.2.60) ผ่านเกณฑ์สำเร็จ 8/8 ข้อ เครื่องมือวัด/ให้คะแนนอยู่ที่ `app/tools/scorecard/` ประเมินซ้ำได้ด้วยคำสั่งสองบรรทัด
