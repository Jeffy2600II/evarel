# S4 แปลงเป็น React + Tailwind ทีละหน้า (ช่วง: ไกล เป้าหมายกับเกณฑ์เท่านั้น)

กลับไปที่ [แผนหลัก](../MASTER-PLAN.md) | ขั้นก่อนหน้า [S3](S3-nextjs-wrap.md) | ขั้นถัดไป [S5](S5-release.md)

## เป้าหมาย
แปลงหน้าของแอปเป็น React ทีละแท็บ และเปลี่ยนการจัดหน้าตาเป็น Tailwind CSS ในหน้าเดียวกัน โดยพฤติกรรมและหน้าตาไม่เปลี่ยน

## ผลลัพธ์ที่ตรวจได้
1. แต่ละหน้าที่แปลงผ่านประตู 3 ชุด (ภาพ 0 พิกเซล ชุดทดสอบ route และฟีเจอร์ ออฟไลน์) ก่อนเริ่มหน้าถัดไป
2. หน้าที่ยังไม่แปลงยังทำงานได้ตามเดิมตลอดช่วงแปลง
3. ไม่ผ่านประตูใด ต้องย้อนกลับหน้านั้น

## การตัดสินใจเรื่อง Tailwind (Master 15 ต.ค. 2026)
Master เลือก Tailwind โดยรับความเสี่ยงต่อประตูภาพ 0 พิกเซลเอง ข้อมูลที่ใช้ตัดสิน (วัดจากโค้ดจริง): ระยะห่างฝังตรง 563 จุดใน 58 ค่า, มุมโค้ง 27 แบบ, ตัวอักษร 30 ขนาด, เงา 21 แบบ, สไตล์ฝังในโค้ด 54 จุด, จุดที่ JavaScript สร้าง HTML พร้อม class 365 จุด รายละเอียดอยู่ใน [S6-apk-and-css-decision-guide.md](S6-apk-and-css-decision-guide.md)

วิธีลดความเสี่ยงที่ผมวางไว้ (ต้องให้ Master รับรอง):
1. ตั้งค่า Tailwind ให้รองรับค่าเฉพาะที่มีอยู่เดิม (เช่น ระยะ 14px, 15px) ก่อน เพื่อให้ผลลัพธ์เดิมเป๊ะ แล้วค่อยรวมค่าใกล้กันทีหลังเป็นงานแยกที่ Master อนุมัติ
2. เปลี่ยนทีละหน้า แต่ละหน้าผ่านประตู 3 ชุดก่อนหน้าถัดไป ไม่ผ่านย้อนกลับหน้านั้น
3. ช่วงที่ยังไม่ครบทุกหน้า แอปมีสองระบบสไตล์ปนกัน ต้องกันไม่ให้ CSS เดิมกับ Tailwind ชนกัน (วิธีกันชนยังไม่ได้ออกแบบ ต้องวัดตอนลองหน้าแรก)
4. การรวมค่าให้เป็นระบบสม่ำเสมอ (ซึ่งเป็นเหตุผลหลักที่เลือก Tailwind) ทำให้ภาพขยับได้ จึงต้องแยกเป็นงานต่างหากที่ Master สั่งชัดเจน ตามกฎ "ดีไซน์ canonical ห้ามเปลี่ยนเอง"

## สถานะ
ยังไม่เริ่ม ยังไม่มีไฟล์ React ในที่เก็บ

## สถานะการเลื่อน
