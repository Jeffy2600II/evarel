# S7 แอป APK ด้วย React Native (ช่วง: ไกล เป้าหมายกับเกณฑ์เท่านั้น)

กลับไปที่ [แผนหลัก](../MASTER-PLAN.md) | ขั้นก่อนหน้า [S6](S6-release.md) | ข้อมูลประกอบการตัดสินใจ [S7-apk-and-css-decision-guide.md](S7-apk-and-css-decision-guide.md) | โครงสร้างระบบและการแบ่งชั้นเผื่อแอป (ตรวจจากโค้ดจริง) [S7-structure-share-design.md](S7-structure-share-design.md)

## การตัดสินใจของ Master (15 ต.ค. 2026)
1. ใช้ **React Native** สร้างแอป เขียนหน้าจอใหม่ ไม่ต้องหน้าตาเหมือนเว็บเป๊ะ
2. APK เป็นเป้าหมายรอง ทำหลัง 2 พ.ย. 2026 ได้ ถ้าทันก็ดี หมุดหมายหลักยังคือเว็บ PWA
3. แจกเป็นไฟล์ตรง ไม่ขึ้น Google Play ยังไม่มีแผนขึ้น Google
4. หน้าที่ของเว็บและแอปคือ **ฟังก์ชันตรงกัน** หน้าตาไม่ต้องเหมือนเป๊ะ ความแข็งแรงของระบบต่างกันตามแพลตฟอร์มได้

## เป้าหมาย
ได้ไฟล์ APK ที่ติดตั้งลง Android ได้ มีฟังก์ชันหลักตรงกับเว็บ และใช้ระบบหลังบ้านชุดเดียวกัน (Supabase, Worker, Edge Function แจ้งเตือน)

## ผลของการเลือก React Native ที่ต้องรับรู้
- **หน้าจอเขียนใหม่ทั้งหมด** ใช้ร่วมกับเว็บได้เฉพาะส่วนที่ไม่ใช่หน้าจอ เช่น การคำนวณกฎแจ้งเตือน การเรียก API การจัดการข้อมูล
- **ประตู 3 ชุดเดิมใช้กับแอปไม่ได้** ภาพเหมือน 0 พิกเซล และชุดทดสอบ route 22 / feature 13 เขียนมาเพื่อเว็บ แอปต้องมีเกณฑ์ของตัวเอง (ดูด้านล่าง) ประตู 3 ชุดยังบังคับใช้กับเว็บเหมือนเดิม
- **Tailwind ของเว็บใช้ในแอปไม่ได้โดยตรง** React Native ไม่มี CSS ปกติ ถ้าอยากใช้แนวคิดเดียวกันต้องมีไลบรารีแยก (เช่น NativeWind) ซึ่งเป็นตัวเลือกที่ยังไม่ได้ตรวจ ห้ามอ้างว่าเข้ากันจนกว่าจะลอง
- **แจ้งเตือน:** Web Push ที่ใช้อยู่ทำงานผ่านเบราว์เซอร์ แอป React Native ไม่ใช้กลไกนี้ ต้องเลือกใหม่ระหว่าง Firebase Cloud Messaging (บริการภายนอกเพิ่ม ต้องตรวจโควตาและเงื่อนไขฟรี) หรือแจ้งเตือนที่ตั้งไว้ในเครื่อง (ไม่พึ่งเซิร์ฟเวอร์ แต่ต้องซิงก์เวลากับข้อมูลที่แก้จากเว็บ) ยังไม่ได้ตัดสิน
- **เซิร์ฟเวอร์ที่ผมใช้ build ไม่มี Android SDK, Java, Gradle** [วัด 15 ต.ค. 2026] build ในเครื่องนี้ไม่ได้ ต้อง build บนบริการภายนอก (เช่น GitHub Actions หรือ EAS Build ของ Expo) ซึ่งยังไม่เคยลองและยังไม่ได้ตรวจโควตาฟรี

## เกณฑ์ที่ตรวจได้ (ร่าง ต้องให้ Master รับรองก่อนใช้)
เนื่องจากประตูภาพไม่ใช้กับแอป ผมเสนอเกณฑ์ใหม่ดังนี้
1. ติดตั้ง APK ลงเครื่อง Android ของ Master ได้ และเปิดแอปได้
2. ล็อกอินได้ทั้งอีเมลกับรหัสผ่านและ Google
3. เพิ่ม แก้ ทำเครื่องหมาย รายการได้ ข้อมูลตรงกับเว็บทั้งสองทาง (แก้จากเว็บแล้วเห็นในแอป และกลับกัน)
4. ใช้งานออฟไลน์ได้ ข้อมูลอยู่ครบหลังปิดเปิดแอป
5. แจ้งเตือนถึงเครื่องตรงเวลาที่ตั้ง (ผ่านกลไกที่เลือก)
6. AI สั่งงานภาษาไทยได้ภายในโควตา
7. เกณฑ์ภาพ: หน้าจอหลักแต่ละหน้าแสดงถูกต้องบนเครื่องจริง ไม่มีส่วนตกขอบหรือถูกตัด (ตรวจด้วยตา ไม่ใช่เทียบพิกเซล)

## สิ่งที่ยังไม่ทราบ (ต้องวัดหรือตรวจก่อนอ้างเป็นข้อเท็จจริง)
- เวลาที่ใช้จริง ยังไม่เคยวัด (และ S3 กับ S5 ก็ยังไม่เคยวัด)
- build APK บนบริการภายนอกได้ภายในงบ 0 บาทหรือไม่
- เลือกใช้ Expo หรือ React Native เปล่า (แต่ละแบบแลกกับความคุมได้และความยากในการ build)
- กลไกแจ้งเตือนในแอป (ข้างบน)
- การเซ็นแอป (keystore): ต้องสร้างครั้งเดียว เก็บเป็นความลับ สำรองอย่างน้อยสองที่ หายแล้วอัปเดตแอปเดิมไม่ได้ ต้องถอนแล้วติดตั้งใหม่และข้อมูลในเครื่องหาย
- ตรรกะส่วนไหนแยกออกมาใช้ร่วมกับเว็บได้จริง — **ตรวจเบื้องต้นแล้ว 31 ต.ค. 2026 (สแกนแบบนิ่ง): 13/23 ไฟล์ core ใช้ร่วมทันที, 7 ไฟล์ต้องแยกโรงงาน HTML ออกก่อน, 3 ไฟล์ต้องทำ adapter — รายละเอียดและการออกแบบ 3 ชั้นที่ [S7-structure-share-design.md](S7-structure-share-design.md)** ยังต้องพิสูจน์ด้วยการ import ทดลองในโครง RN จริงก่อนถือเป็นข้อเท็จจริงเด็ดขาด
