# S5 เปลี่ยนการจัดหน้าตาเป็น Tailwind ทีละหน้า (ช่วง: ไกล เป้าหมายกับเกณฑ์เท่านั้น)

กลับไปที่ [แผนหลัก](../MASTER-PLAN.md) | ขั้นก่อนหน้า [S4](S4-typescript.md) | ขั้นถัดไป [S6](S6-release.md)

## เป้าหมาย
เปลี่ยนการจัดหน้าตาของหน้าที่เป็น React แล้วเป็น Tailwind CSS ทีละหน้า โดยพฤติกรรมและหน้าตาไม่เปลี่ยน

ขอบเขตหลังปรับ (16 ต.ค. 2026 ตามคำสั่ง Master): งานแปลงเป็น React ย้ายไปรวมใน [S4](S4-typescript.md) แล้ว ขั้นนี้ทำต่อจาก S4 และอาศัยว่าหน้าเป็น React แล้ว

## ผลลัพธ์ที่ตรวจได้
1. แต่ละหน้าที่เปลี่ยนเป็น Tailwind ผ่านประตู 3 ชุด (ภาพ 0 พิกเซล ชุดทดสอบ route และฟีเจอร์ ออฟไลน์) ก่อนเริ่มหน้าถัดไป
2. หน้าที่ยังไม่เปลี่ยนยังทำงานและหน้าตาเหมือนเดิมตลอดช่วงเปลี่ยน
3. ไม่ผ่านประตูใด ต้องย้อนกลับหน้านั้น

## การตัดสินใจเรื่อง Tailwind (Master 15 ต.ค. 2026)
Master เลือก Tailwind โดยรับความเสี่ยงต่อประตูภาพ 0 พิกเซลเอง ข้อมูลที่ใช้ตัดสิน (วัดจากโค้ดจริง): ระยะห่างฝังตรง 563 จุดใน 58 ค่า, มุมโค้ง 27 แบบ, ตัวอักษร 30 ขนาด, เงา 21 แบบ, สไตล์ฝังในโค้ด 54 จุด, จุดที่ JavaScript สร้าง HTML พร้อม class 365 จุด รายละเอียดอยู่ใน [S7-apk-and-css-decision-guide.md](S7-apk-and-css-decision-guide.md)

วิธีลดความเสี่ยงที่ผมวางไว้ (ต้องให้ Master รับรอง):
1. ตั้งค่า Tailwind ให้รองรับค่าเฉพาะที่มีอยู่เดิม (เช่น ระยะ 14px, 15px) ก่อน เพื่อให้ผลลัพธ์เดิมเป๊ะ แล้วค่อยรวมค่าใกล้กันทีหลังเป็นงานแยกที่ Master อนุมัติ
2. เปลี่ยนทีละหน้า แต่ละหน้าผ่านประตู 3 ชุดก่อนหน้าถัดไป ไม่ผ่านย้อนกลับหน้านั้น
3. ช่วงที่ยังไม่ครบทุกหน้า แอปมีสองระบบสไตล์ปนกัน ต้องกันไม่ให้ CSS เดิมกับ Tailwind ชนกัน (วิธีกันชนยังไม่ได้ออกแบบ ต้องวัดตอนลองหน้าแรก)
4. การรวมค่าให้เป็นระบบสม่ำเสมอ (ซึ่งเป็นเหตุผลหลักที่เลือก Tailwind) ทำให้ภาพขยับได้ จึงต้องแยกเป็นงานต่างหากที่ Master สั่งชัดเจน ตามกฎ "ดีไซน์ canonical ห้ามเปลี่ยนเอง"
