# F7 แยกเว็บ แอป แชร์ หลังบ้าน (รื้อโครงราก 1 ครั้ง)

กลับไปที่ [แผนโรงงาน](../FACTORY-PLAN.md) | ขั้นก่อนหน้า [F6](F6-m-layer-order.md) | เอกสารประกอบ [S7-structure-share-design.md](../steps/S7-structure-share-design.md)

## การตัดสินของ Master (31 ต.ค. 2026)

1. ระบบปัจจุบัน "ซับซ้อนเกินและดูซ้ำซ้อน": ของฝั่งเว็บกระจายหลายโฟลเดอร์ มีหน้าอยู่ในโฟลเดอร์ app แล้วข้างในยังมีโฟลเดอร์ web อีก
2. "ถ้าเป็นออกแบบสำหรับตัวเว็บก็คือต้องเป็นเว็บ ตัว app ก็คือต้องเป็นแอป" ให้แต่ละฝั่งพัฒนาได้ง่าย ไปทิศทางเดียวกัน
3. ยังไม่สร้างแอปมือถือ แต่ "จะทำให้โครงสร้างมันเหมาะสมก่อน" คือทำโครงรากนี้ตอนนี้ ก่อนถึง S7
4. โครงใหม่นี้แทนที่ผังโฟลเดอร์ใน FACTORY-PLAN ข้อ 2 (โซนโรงงานยังเป็นห้าโซนเหมือนเดิม เพียงย้ายที่อยู่)

## เป้าหมาย

รากของรีโปแยกตามแพลตฟอร์มชัดเจน อ่านรู้เลยว่าอะไรคือเว็บ อะไรคือแอป อะไรใช้ร่วม อะไรคือหลังบ้าน อะไรคือของเก่า โดยผู้ใช้ไม่เห็นความต่างใด ๆ (ย้ายที่อยู่ไฟล์ ไม่แตะเนื้อไฟล์)

## ผลลัพธ์ที่ตรวจได้ (ประตูของ F7)

1. รากมี 5 บ้าน: `web/` `app/` `core/` `backend/` `archive/` และ `tools/` รวมเครื่องมือโรงงาน
2. `git diff -M` ของไฟล์ที่ย้ายต้องเป็นการเปลี่ยนชื่อเกือบล้วน (ไฟล์ที่แก้จริงมีรายชื่อชัด: สคริปต์บิลด์ ทดสอบ กติกา เอกสาร คอนฟิก index.html/sw.js ที่เปลี่ยนพาธเสิร์ฟ js/app เป็น js/engine และ app.css ที่หัวไฟล์เปลี่ยนตามตัวสร้าง)
3. build:web:forge ผ่าน และ build_integrity ผ่าน (สายพาน CI ไม่พัง)
4. checker ทุกกล่องผ่าน, แผนที่โรงงานวาดใหม่แล้ว commit, m_progress ยังรายงาน F6 จบได้
5. ประตูภาพ 32 ฉาก: ผลหลังย้ายเหมือนผลก่อนย้ายทุกฉาก (ตัวควบคุมวิ่งบนเครื่องเดียวกัน เบราว์เซอร์ตัวเดียวกัน) เพราะไฟล์ที่เสิร์ฟเป็นไบต์เดิม (หมายเหตุ: รอบนี้เครื่องวิ่ง chromium 1200 แทน 1243 ที่ pin ไว้ ผลเทียบเดโมจึงตก 16 ฉากทั้งก่อนและหลังย้ายเหมือนกัน ตัวเลขที่ใช้ตัดสินจึงเป็น "หลังตรงกับก่อน" ไม่ใช่ "0 พิกเซลเทียบเดโม")
6. เลขรุ่นขยับและมีโน้ตรุ่น (ไฟล์ที่ส่งถึงผู้ใช้ย้ายที่อยู่ ถือเป็นการเปลี่ยนของที่ส่ง)
