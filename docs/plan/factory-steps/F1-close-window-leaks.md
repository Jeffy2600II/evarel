# F1 ปิดรอยรั่ว window (ช่วง: ใกล้ รายละเอียดเต็ม)

กลับไปที่ [แผนเสริม](../FACTORY-PLAN.md) | ก่อนหน้า [F0](F0-contract-baseline.md) | ถัดไป [F2](F2-factory-tools.md)

## เป้าหมาย
ทำให้ชั้น m มีเส้นแบ่งที่เครื่องตรวจมองเห็น คือ ES module จริง (`import`/`export`) ครบทุกไฟล์ ไม่ใช่ `Object.assign(window, ...)` นี่คือสิ่งที่ S4 วางไว้เป็นขั้นกลางแล้วทำไปได้ 01-07 (หน่วย s4f-base-esm) ที่เหลือ 08-25 กับ 00-head ค้างอยู่ ขั้นนี้คือการทำต่อตามวิธีเดิมที่พิสูจน์แล้ว
เหตุที่ต้องทำก่อนโรงงาน: ถ้าไฟล์ยังรับของจากส่วนกลางลับๆ ตัวตรวจไม่รู้ว่ากล่องหนึ่งพึ่งอะไรบ้าง "ทะเบียนใครใช้ใคร" กับ "แก้ย้อนรายกล่อง" เป็นไปไม่ได้

## ผลลัพธ์ที่ตรวจได้
1. ไฟล์ใน `app/src/m` ที่มี `Object.assign(window` เหลือ 0 จาก 26 (เส้นฐาน 26)
2. ไฟล์ที่ไม่มี import และไม่ใช่ปลายทางที่ถูกต้อง เหลือ 0 (เส้นฐาน 21 ไฟล์ไม่มี import)
3. `types/shim-globals.d.ts` (declare const 97 ชื่อ) ลดจำนวนลงตามที่ shim หายไป สุดท้ายเป็น 0 หรือเหลือเฉพาะที่ระบุเหตุผล
4. ตัววัด dependency (`tools/dep_manifest.mjs`) รายงานย้อนทิศ 0 วงจร 0 ก่อนและหลัง
5. ประตูเดิมทุกชุดผ่านหลังทุกหน่วย; อัปเกรด service worker จากรุ่นเก่าผ่านครบ (ไฟล์ที่ผู้ใช้ได้รับเปลี่ยนชื่อเดิม ต้อง bump รุ่นแคชทุกครั้ง)
6. `window` ที่เหลือใน `app/src` แยกประเภทครบ: บูต/แพลตฟอร์ม (อนุญาต, ระบุในไฟล์ "กฎของบ้านนี้") กับรับของข้ามกล่อง (ต้องเป็น 0)

## วิธีการ (ใช้วิธีที่ S4 พิสูจน์แล้ว ไม่คิดใหม่)
- แปลงทีละกลุ่ม ไม่ใช่ทั้งชั้นในรอบเดียว กลุ่มเล็กก่อน: ui (09,11,12) > services (10,16,18,20,24) > core (08,15) > views (13,17,19,21,22,23) > actions (14,25) ลำดับสุดท้ายอ้างอิงจาก dep_manifest ไม่ใช่เดา
- วัด import จริงจากโค้ด ไม่เดา (เหมือน s4f-base-esm)
- แก้เครื่องมือก่อนถ้าเครื่องมือพัง (เคยเจอ parse sourceType ผิดกับไฟล์ ES)
- ห้ามสร้างวัตถุ `S` ใหม่ทับ (บทเรียนจาก today_equiv: โมดูลที่ import S ยังเห็นของเก่า)
