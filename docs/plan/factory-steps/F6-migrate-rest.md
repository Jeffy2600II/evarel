# F6 ขยายทีละหน้า (เอกสาร B8 ข้อ 3 และ B6 ข้อ 6)

กลับไปที่ [แผนเสริม](../FACTORY-PLAN.md) | ก่อนหน้า [F5](F5-conveyor.md)

## เป้าหมาย
ตามเอกสาร: หน้าใหม่เกิดในโครงใหม่ทั้งหมด หน้าเก่าย้ายทีละกล่อง ไม่รื้อวันเดียว จบเมื่อทุกหน้าอยู่ใน `pages/` และชั้น `m/` เดิมหมด รายละเอียดลำดับขยายต่อเมื่อ F4 จบ เพราะต้องอิงสิ่งที่เรียนรู้จากกล่องนำร่อง

## ผลลัพธ์ที่ตรวจได้
1. ทุกหน้าตามตารางจับคู่ข้อ 3 ของแผนภาพรวมอยู่ในกล่องสามชั้นครบ
2. ชิ้นส่วนร่วม (`item-row, nav, sheet, dialog`) อยู่ใน `shared/`
3. `app/src/m` ว่าง ตรรกะของ 26 ไฟล์เดิมกระจายเข้า `pages/` `shared/` `data/` ตามหน้าที่
4. กล่องที่ผ่านเครื่องตรวจและแผ่นตรวจรับเท่านั้นที่ออกจากโซนกักรอตรวจ
5. ย้อนกลับได้รายกล่อง

## ข้อสังเกตจากของที่มีอยู่
- ลำดับย้ายเสนอ: หน้าเล็กก่อน (auth, detail, settings, focus) แล้ว ai, form, today และ calendar ท้ายสุดเพราะพึ่งตัวปฏิทินกับ store ร่วม
- `22-views__auth.ts` ใหญ่สุดของ m (22,333 ไบต์) ต้องแบ่งกล่องย่อยตามกฎกล่องล้นแบ่ง
- ลำดับจริงตัดสินหลังเห็นผลนำร่อง

## สิ่งที่ยังไม่ทราบ
- ลำดับย้ายที่ดีที่สุด (รอผล F4)
- เวลาที่ใช้ต่อกล่อง (ยังไม่เคยวัด)

## ผลวัดก่อนเริ่ม (Oct 28, 2026) วัดจากรีโปจริง ไม่ใช่การประเมิน
ของที่เหลือแบ่งเป็นสองชั้น ย้ายด้วยวิธีต่างกัน

| ชั้น | ไฟล์ | ขนาด | ลักษณะ |
|---|---|---|---|
| React (`app/src/react`) | หน้า 12 + โครงรัน 2 (`runtime.js`, `store.js`) | หน้าเล็กสุด `auth` 1.7 KB ใหญ่สุด `form` 12.8 KB | ย้ายเป็นกล่องแบบ F4 ได้ทีละหน้า มีถาดครบแล้ว (F3.3) เกราะเทียบ HTML มีทุกหน้า **ยกเว้น** `detail`, `dialog`, `sheet`, `item-row` |
| ชั้น `m/` | 26 ไฟล์ | 217,878 ไบต์ | ตรรกะจริง ผูกกันผ่าน `window`, `ST`, `UI` ทั่วชั้น |

ข้อสังเกตที่เปลี่ยนแผน:
1. หน้า React หลายหน้าเป็นตัวห่อบางที่แสดง HTML สตริงจาก `m/` (เช่น `auth.jsx` 19 บรรทัด ห่อ `22-views__auth.ts` 22 KB) ย้ายแค่ตัวห่อ = ได้ชื่อใน `pages/` แต่ `m/` ไม่ลดเลย
2. `21-views__detail.ts` (2 KB) เป็นตัวคุมสถานะ ไม่ใช่เนื้อหน้า ผูก `ST.DETAIL` ที่หลายที่อ่าน ย้ายเดี่ยวไม่ได้โดยขยับ `window`
3. ชิ้นร่วมตามข้อ 2 ของผลลัพธ์ (`item-row, nav, sheet, dialog`) ต้องอยู่ `shared/` แต่ท่อบิลด์รับกล่องเฉพาะ `app/pages/<ชื่อ>/<Pascal>Page.jsx` ต้องเพิ่มเส้นทางบิลด์สำหรับ `shared/` ก่อนย้ายชิ้นเหล่านี้
4. เกณฑ์ "m ว่าง" ทำได้ แต่เป็นงานหลายรอบ ต้องย้ายตรรกะเข้าถาดและ `core/` ทีละชิ้นแบบ F3.3
