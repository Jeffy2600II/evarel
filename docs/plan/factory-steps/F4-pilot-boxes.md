# F4 กล่องนำร่อง (ช่วง: กลาง)

กลับไปที่ [แผนเสริม](../FACTORY-PLAN.md) | ก่อนหน้า [F3](F3-tokens-contracts.md) | ถัดไป [F5](F5-conveyor.md)

## เป้าหมาย
ตามเอกสารโรงงาน B8: พิมพ์ 1-2 หน้าจริงด้วยเบ้าจูน ลองทุกกลไกกับของจริง ติดตรงไหนปรับก่อนขยาย
ข้อนี้คือจุดพิสูจน์ว่าแนวคิดโรงงานใช้ได้กับโค้ดจริงของ Evarel ไม่ใช่แค่ในกระดาษ และเป็นตัวตัดสินว่า "ขนาดล้น" ควรเป็นเท่าไร

## การเลือกหน้านำร่อง (เสนอ ให้ Master ปรับ)
เกณฑ์เลือก: หน้าเล็ก พึ่งพาน้อย มีเทสต์เทียบ HTML ตรงทุกไบต์อยู่แล้ว
| ตัวเลือก | เหตุผล | ข้อควรระวัง |
|---|---|---|
| หน้าสถิติ (`stats`) | `stats.jsx` เล็ก (4,728 ไบต์ 47 บรรทัด) มีทั้ง `core/stats.ts` คำนวณบริสุทธิ์ และเทสต์เทียบ HTML `tests/stats_html_equiv.test.mjs` | ใช้ข้อมูลร่วมกับ `07-services__stats` |
| หน้ารายการ (`all`) | `all.jsx` เล็กมาก (2,081 ไบต์ 24 บรรทัด) มี all_interact 13/13 | พึ่ง item-row ร่วมกับ today |
เสนอ: เริ่มจาก `stats` กล่องแรก แล้ว `all` กล่องที่สอง (ใช้ item-row ร่วม จึงลองชิ้นส่วนกลางได้จริง)
ไม่เสนอ today/calendar เป็นนำร่อง: พึ่ง FullCalendar และ store ร่วม ซับซ้อนเกินสำหรับการเรียนรู้รอบแรก

## ผลลัพธ์ที่ตรวจได้
1. กล่อง `stats` และ `all` อยู่ในโครงโรงงานครบสามชั้น สร้างจากเบ้าจูนหรือย้ายเข้าตามโครงที่เบ้าจูนผลิต
2. หน้านำร่องผ่านประตูเดิมทุกชุดโดยภาพ 0 พิกเซล และเทสต์เทียบ HTML (`stats_html_equiv`, `all_interact` 13/13 ตามบันทึก S4 ยังไม่ได้รันซ้ำในเทิร์นนี้) ไม่ต้องแก้เทสต์
3. แผ่นตรวจรับประจำกล่อง (ผ่านตรวจ + บัตรครบ + ลงทะเบียน ครบสามข้อ) ผ่านทั้งสองกล่อง
4. บันทึก "ติดตรงไหน" เป็นไฟล์เดียว: ทุกครั้งที่เบ้าจูน/ตัวตรวจ/แม่พิมพ์ไม่พอ ต้องบันทึกและปรับเครื่องมือก่อนขยาย
5. ได้ตัวเลขจริงสำหรับเกณฑ์ "กล่องล้น" (ขนาด/จำนวนไฟล์ต่อกล่อง) จากสองกล่องนี้ แล้วเสนอให้ Master ตัดสิน
6. วัดว่าการเพิ่มหน้าใหม่สมมติ 1 หน้าด้วยเบ้าจูนใช้กี่ขั้นตอนเทียบกับเส้นทางเดิม (ตัวเลขรองรับ "พัฒนาง่ายขึ้น" ด้วยการวัด ไม่ใช่คำพูด)

## จุดสังเกตที่ต้องจับตา (จากบทเรียนใน handoff S4)
- หน้า React ใหม่ต้องแตะ 3 จุดเดิม (REACT_PAGES, เงื่อนไข re-render, sw CORE) เบ้าจูนต้องทำสามจุดนี้ให้ครบโดยอัตโนมัติ ไม่เช่นนั้นกล่องใหม่จะเงียบพัง
- ก่อนเขียนทับ container ที่ React ถือ ต้อง `unmountOne` ก่อนเสมอ
- ไฟล์ที่ esbuild สร้างห้ามก๊อปทับ ใช้ `build-react` แล้ว `--check`
- เทสต์ที่ seed ข้อมูลต้องใส่ field ตรง schema (เช่น `days` อยู่ใน `repeat`)
