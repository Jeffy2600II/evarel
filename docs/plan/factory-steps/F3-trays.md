# F3 ถาดข้อมูล (เอกสาร B2 ชั้น 3 และข้อ 4 ของลำดับแนวคิด)

กลับไปที่ [แผนเสริม](../FACTORY-PLAN.md) | ก่อนหน้า [F2](F2-factory-tools.md) | ถัดไป [F4](F4-pilot-boxes.md)

## เป้าหมาย
ข้อมูลวิ่งทางเดียว รับ → ปรุง → เสิร์ฟ ผ่านถาดที่กำหนดรูป (เอกสาร B6 ข้อ 3) หน้าจอไม่ดึงของเอง ของผิดรูปเข้าไม่ได้ ข้อมูลพังรู้ทันทีว่าตู้ไหน
ถาดประจำหน้าอยู่ในกล่องเป็นไฟล์ `<หน้า>.tray` ถาดร่วมแยกตามโมดูลอยู่ใน `data/`

## ผลลัพธ์ที่ตรวจได้
1. ทุกกล่องมี `.tray` ประกาศรูปข้อมูลที่รับ กล่องไม่อ่านจากส่วนกลางนอกถาด
2. `window` ที่ชั้น React (147 จุดเส้นฐาน) และชั้น m (89 จุด) แยกประเภทแล้ว ส่วนที่เป็นการรับของข้ามกล่องถูกแทนด้วยถาดจนเหลือ 0
3. ข้อมูลผิดรูปถูกจับที่ถาด ฉีดข้อมูลผิดรูปหนึ่งชนิดต่อถาดแล้วเห็นข้อผิดพลาดชี้ถูกกล่อง
4. ตรรกะคำนวณบริสุทธิ์เดิม (`core/dates, schedule, stats, today`) อยู่ใน `data/` และหน้ารับผ่านถาด

## งานย่อย
| # | งาน |
|---|---|
| F3.1 | วัด `window` แยกอ่าน เขียน บูต คอมเมนต์ เป็นตารางต่อไฟล์ |
| F3.2 | ออกแบบรูปถาดมาตรฐานหนึ่งแบบ ใช้เหมือนกันทุกกล่อง |
| F3.3 | แปลงข้อมูลที่ไหลผ่านส่วนกลางเป็นถาดทีละกลุ่มข้อมูล |
| F3.4 | ถอดการอ้าง `window` ตามที่ถาดแทนได้ |

## ความเสี่ยง
| ความเสี่ยง | วิธีลด |
|---|---|
| ลำดับโหลดเปลี่ยนเมื่อเลิกใช้ส่วนกลาง | เทสต์ลำดับเดิม ย้อนรายกลุ่ม |
| `window` ส่วนหนึ่งเป็นกลไกบูตของแพลตฟอร์ม ไม่ใช่การรับของข้ามกล่อง | แยกประเภทใน F3.1 ก่อนถอด ส่วนที่จำเป็นระบุเหตุผลในไฟล์กฎของบ้านนี้ |
