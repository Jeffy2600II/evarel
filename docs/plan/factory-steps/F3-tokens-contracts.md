# F3 แม่พิมพ์กลางและถาดข้อมูล (ช่วง: กลาง)

กลับไปที่ [แผนเสริม](../FACTORY-PLAN.md) | ก่อนหน้า [F2](F2-factory-tools.md) | ถัดไป [F4](F4-pilot-boxes.md)

## เป้าหมาย
สองเรื่องที่เป็นข้อ 3 และ 4 ในลำดับแนวคิดของ Master:
- แม่พิมพ์กลาง (design tokens): สี ฟอนต์ ระยะห่าง มุม เงา มาจากตารางจุดเดียว เปลี่ยนฟอนต์ทั้งเว็บ = แก้บรรทัดเดียว
- ถาดข้อมูล (data contracts): ข้อมูลเข้ากล่องผ่านถาดที่กำหนดรูป หน้าจอไม่ดึงของเองจากส่วนกลาง ของผิดรูปเข้าไม่ได้
ข้อจำกัดสูงสุด: ผู้ใช้เห็นเหมือนเดิมทุกพิกเซล ขั้นนี้จึงเป็นการ "ตั้งชื่อค่าเดิม" ไม่ใช่การปรับดีไซน์

## ผลลัพธ์ที่ตรวจได้
### แม่พิมพ์กลาง
1. ทุกค่าสี ระยะ มุม เงา ฟอนต์ที่ใช้อยู่จริง ถูกจัดทะเบียนเป็น token พร้อมค่าเดิมตรงตัว (ไม่ปัดเศษ ไม่รวมค่าใกล้กัน)
2. ค่าสีฝังตรงนอกแม่พิมพ์ลดจากเส้นฐาน (app.css 152 จุด / design.css 128 จุด วัดเทิร์นนี้) เหลือ 0 หรือเหลือเฉพาะที่ระบุเหตุผล
3. ภาพ 0 พิกเซลทุกฉากหลังแปลง (หลักฐานว่าตั้งชื่อค่าเดิมจริง)
4. ห้องโชว์แม่พิมพ์ (component gallery) หน้าเดียวแสดงทุก token และชิ้นส่วนกลาง เป็นกระจกบอกว่าแม่พิมพ์เพี้ยนตรงไหน
5. ฟอนต์ยังเป็นฟอนต์ระบบตามที่ Master ชอบ ไม่เพิ่มฟอนต์ที่โหลดเอง
### ถาดข้อมูล
6. แต่ละกล่องมี contract ประกาศรูปข้อมูลที่รับ (ชนิดเป็น TypeScript) กล่องไม่อ่านจากส่วนกลางนอก contract
7. `window.` ที่ชั้น React (147 จุดเส้นฐานเทิร์นนี้) แยกประเภทแล้ว และส่วนที่เป็นการรับของข้ามกล่องถูกแทนด้วย contract จนเหลือ 0
8. ข้อมูลผิดรูปถูกจับที่ถาด (ทดสอบฉีดข้อมูลผิดรูป 1 ชนิดต่อ contract แล้วเห็นข้อผิดพลาดชี้ถูกกล่อง)

## ความสัมพันธ์กับ S5 Tailwind (ต้องอ่านก่อนเริ่ม)
`tailwind.config.cjs` ปัจจุบันชี้สีไปที่ CSS variable `--c-*` (25 ตัว) และมีคอมเมนต์ว่า "ห้ามแก้ค่าตรงนี้เอง ต้องสั่งจาก Master" F3 ต้องไม่แตะค่าใน config นั้น และไม่เปลี่ยนลำดับหรือเกณฑ์ของ S5 ทำได้เฉพาะเติมชื่อ token ที่ยังไม่มี โดยให้ชื่อใหม่ชี้ค่าเดิมชุดเดียวกัน (ลำดับระหว่างสองงานตาม D4)
