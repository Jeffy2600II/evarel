# F5 สายพานอัตโนมัติ (เอกสาร B5)

กลับไปที่ [แผนเสริม](../FACTORY-PLAN.md) | ก่อนหน้า [F4](F4-pilot-boxes.md) | ถัดไป [F6](F6-migrate-rest.md)

## เป้าหมาย
ต่อเครื่องมือ F2 เข้า GitHub Actions ตามเอกสาร B5 ทั้งสี่ข้อ:
1. วาดแผนที่ทุกครั้งที่ push สแกนโครงสร้างจริงแล้ววาดใหม่ ไม่มีวันล้าสมัย
2. ตรวจกติกา ไม่ผ่าน = ไม่ปล่อย กฎเป็นเครื่องตรวจ ไม่ใช่ความจำ
3. ทะเบียนใครใช้ใคร
4. X-ray ตรวจรายหน้า

ต่อยอด `.github/workflows/web.yml` ที่มีอยู่ (ตรวจโน้ตรุ่น ตรวจไฟล์คอมไพล์ตรงซอร์ส build ตรวจ release) เพิ่ม job เข้าไฟล์เดิม ไม่สร้าง workflow ซ้อน

## ผลลัพธ์ที่ตรวจได้
1. ทุก push วาดแผนที่ใหม่เองและเผยแพร่เป็นไฟล์เปิดอ่านได้ ลิงก์ชี้ไฟล์จริง
2. push ตัวอย่างที่ฝ่าฝืนกฎแกนหนึ่งข้อถูกตีกลับพร้อมบอกข้อและเหตุผล
3. เวลารันของ job ใหม่วัดจริงแล้ว อยู่ในโควตาฟรีของ GitHub Actions
4. ถอด job ออกแล้วเครื่องตรวจยังรันมือได้ด้วยคำสั่งเดียว

## งานย่อย
| # | งาน |
|---|---|
| F5.1 | วัดเวลาและโควตาของตัวตรวจและตัววาดแผนที่ก่อนผูก |
| F5.2 | เพิ่ม job เข้า workflow เดิม |
| F5.3 | เผยแพร่แผนที่โดยไม่ commit กลับเข้ารีโป (กันวน CI) |
| F5.4 | ฉีดกติกาผิดบนสาขาทดลอง ยืนยันว่าสายพานตีกลับจริง |

## ความเสี่ยง
| ความเสี่ยง | วิธีลด |
|---|---|
| แผนที่ commit กลับแล้วชน hook หรือวน CI | เผยแพร่เป็น artifact หรือหน้าแยก |
| workflow ติดตั้ง web-shell แยก ทำให้ job ใหม่ช้า | ใช้แคชเดิมของ job `check` |
