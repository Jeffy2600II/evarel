# F5 สายพานอัตโนมัติ (ช่วง: กลาง)

กลับไปที่ [แผนเสริม](../FACTORY-PLAN.md) | ก่อนหน้า [F4](F4-pilot-boxes.md) | ถัดไป [F6](F6-migrate-rest.md)

## เป้าหมาย
ต่อเครื่องมือ F2 เข้า GitHub Actions ที่มีอยู่ (`.github/workflows/web.yml`) ให้ "กฎเป็นเครื่องตรวจ ไม่ใช่ความจำ":
- วาดแผนที่ทุกครั้งที่ push (ไม่มีวันล้าสมัย)
- ตรวจกติกา ไม่ผ่าน = ไม่ปล่อย
- ทะเบียนใครใช้ใคร และ X-ray รายกล่อง

ขอบเขตที่ต้องชัด: workflow ปัจจุบันจำกัดที่ develop และ forge เท่านั้น production ไม่มี job ใดแตะ F5 ต้องคงข้อนี้ (กฎ Master: ห้ามแตะ production โดยพลการ)

## ผลลัพธ์ที่ตรวจได้
1. job ใหม่ใน workflow เดิม (ไม่สร้างไฟล์ workflow ซ้อน) รันตัวตรวจและตัววาดแผนที่ทุก push บน develop
2. push ตัวอย่างที่ฝ่าฝืนกฎ 1 ข้อถูกตีกลับ (ในโหมดบล็อก) หรือแสดงคำเตือนพร้อมเหตุผล (ในโหมดเตือน) ตามผล D3
3. แผนที่ที่วาดถูกเผยแพร่เป็นไฟล์ที่เปิดอ่านได้ ลิงก์ในแผนที่ชี้ไฟล์จริง
4. เวลารันของ job ใหม่วัดจริงแล้วอยู่ในโควตาฟรีของ GitHub Actions (ยังไม่เคยวัด)
5. ไม่มีขั้นตอนของคนที่ต้องจำ: ถ้าถอด job ออก ตัวตรวจยังรันมือได้ด้วยคำสั่งเดียว

## ความเสี่ยง
| ความเสี่ยง | ผลกระทบ | วิธีลด |
|---|---|---|
| ตัวตรวจบล็อกงานเร่งด่วนที่ไม่เกี่ยว | ขวางการปล่อย | มีทางข้ามที่ Master เป็นผู้อนุมัติเท่านั้น และบันทึกทุกครั้งที่ข้าม |
| แผนที่ commit กลับเข้ารีโปแล้วชนกับ pre-commit hook หรือวนลูป CI | CI วนไม่จบ | เผยแพร่เป็น artifact/หน้าแยก ไม่ commit กลับ (ต้องยืนยันวิธีใน F5.3) |
| workflow ปัจจุบันใช้ติดตั้ง web-shell แยก (ทำ symlink) ทำให้ job ใหม่ช้า | เกินโควตา | ใช้แคชเดิมของ job `check` |
