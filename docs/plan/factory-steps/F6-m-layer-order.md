# F6 ลำดับย้ายชั้น `m/` ทั้ง 26 ไฟล์ (ข้อเสนอ เพื่อให้ Master เลือก ยังไม่ได้เริ่มย้าย)

กลับไปที่ [F6](F6-migrate-rest.md) | วัดจากรีโปจริง 29 ต.ค. 2026 ที่ commit `17aeeba`

## ภาพรวม
หน้า React ย้ายครบ 14 กล่องแล้ว แต่ `app/src/m` ยังมี **26 ไฟล์ 217,878 ไบต์** (เส้นฐาน F0: 217,563) ที่ย้ายมาทั้งหมดเป็นตัวห่อ ตรรกะจริงยังอยู่ที่ `m/` ตามที่ F6 เตือนไว้เอง

## ข้อค้นพบที่เปลี่ยนวิธีจัดลำดับ
1. **`25-actions.ts` (20 KB, ผูก `ST`/`UI` 139 จุด) เป็นศูนย์กลาง** ไฟล์ที่ดูย้ายง่ายเพราะผู้อ่านน้อย (`18-ai-live`, `24-legacy-import`, `21-detail`, `19-settings`, `11-popover`) ผู้อ่านเกือบทั้งหมดคือ `25-actions` ย้ายออกครั้งใดต้องแก้ทางเรียกใน actions ทุกครั้ง จึงไม่ใช่ไฟล์เดี่ยว
2. **ผู้อ่านนับจากการค้นชื่อ** ไม่เห็นการเรียกผ่านสตริงหรือเหตุการณ์ตอนรัน (เช่น `data-act` ที่ `25-actions` ส่งต่อ) ตัวเลขผู้อ่านจึงเป็นขอบล่าง ไม่ใช่ค่าจริง
3. **"เทสต์อ้างชื่อไฟล์" ไม่เท่ากับ "ตรวจเนื้อไฟล์"** หลายเทสต์โหลดไฟล์ `00` ถึง `12` เป็นฐาน shim แล้วตรวจอย่างอื่น จึงนับเป็นความคุ้มกันจริงไม่ได้ ข้อมูลที่เชื่อได้คือไฟล์ที่ **ไม่มีเทสต์อ้างเลย**: `08-undo`, `10-notify`, `11-popover`, `16-ai-quota`, `18-ai-live`, `20-calendar`, `21-detail`, `24-legacy-import`
4. **ชุดภาพ 30 ฉากไม่มีฉากหน้า AI** ไฟล์ที่ผูกหน้า AI (`16`, `17`, `18`) ไม่มีเกราะภาพเลย

## สิ่งที่ยังไม่ทราบ (ไม่เดา)
- **เวลาต่อไฟล์:** ยังไม่เคยวัด หน้า React ใช้เทิร์นละกล่องและกล่องหนึ่งใช้หลายรอบเพราะบั๊กที่ตัวเทียบจับ ไฟล์ `m/` ซับซ้อนกว่าและมีผู้อ่านซ่อน คาดว่านานกว่า แต่ไม่มีตัวเลข
- **กลุ่ม D ย้ายได้จริงหรือไม่ ไม่ทราบ:** ถ้า `window` เป็นสัญญาของชั้น boot (BOOT 37 จุดที่ F3 จัดว่าถอดไม่ได้) บางไฟล์จะย้ายไม่ได้ตามเกณฑ์ "m ว่าง" ต้องให้ Master ตัดสินว่ายอมรับขอบเขตนี้หรือไม่
- **ฉากภาพสำหรับ A/C:** ต้องเพิ่มฉากหน้า AI และหน้าตั้งค่ารายละเอียดก่อน ไม่งั้นเกราะภาพไม่เห็นความเสียหายของกลุ่มเหล่านี้
