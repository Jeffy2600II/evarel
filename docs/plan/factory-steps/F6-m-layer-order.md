## ผลบวกลวงของวงจร (ทำไมตัวเลขนี้ต้องระวัง)
เครื่องนับแบบค้นชื่อเจอ 15 คู่สองทางตอนแรก ลดเหลือ 0 หลังตรวจแต่ละคู่ สาเหตุที่ตัวนับเข้าใจผิด ซึ่งผู้ย้ายรอบถัดไปต้องรู้:
- **`date`** (5 คู่ที่ชี้ไป `25-actions`): ใน 05, 14, 15, 17, 19, 20, 22 เป็นคีย์วัตถุ (`UI={date:TODAY}`), ตัวแปรท้องถิ่น (`let date=TODAY`) หรือสตริง (`endMode==='date'`) ไม่ใช่ฟังก์ชัน `date()` ของ `25-actions`
- **`target`** (`06`↔`09`): `e.target` ของเหตุการณ์ กับ `target` ที่ import จาก `core/schedule`
- **`tick`** (`09`↔`15`): `09` มี `const tick` ของตัวเองสำหรับวัดประสิทธิภาพ (`PERF_PROBE_MS`) ไม่ใช่ `tick()` ของ `15-timer`
- **`pad` `wait`:** `10-notify` มี `const pad` ของตัวเอง (เติม base64) `22-live-sync` มี `const wait` ของตัวเอง (ระยะถอยหลัง retry) ไม่ใช่ `pad`/`wait` ของ `02`/`04` ตัวนับตัดชื่อที่ไฟล์ประกาศเองออกอัตโนมัติ (`declaresLocally`) แทนการไล่ใส่รายการยกเว้นทีละชื่อ
- **ข้อจำกัดที่ยังอยู่:** เมทริกซ์นับจากการค้นชื่อ ไม่เห็นการเรียกผ่านสตริง (`data-act`) หรือเหตุการณ์ตอนรัน ผู้อ่านจริงอาจมากกว่าตัวเลข จึงเป็นขอบล่าง ไม่ใช่ค่าจริง

กติกาเลือกไฟล์ถัดไป: เริ่มจากชั้นต่ำสุดที่ยังมีไฟล์ แล้วเลือกไฟล์ที่มีผู้อ่านน้อยก่อน ย้ายไฟล์ที่ชั้นสูงกว่าได้เฉพาะเมื่อไฟล์ที่มันพึ่งย้ายแล้วหรือไม่ผูกชื่อกัน ตัวนับวัดจากข้อความโค้ด จึงเป็นขอบล่างของผู้อ่านจริง

## ข้อควรระวังที่วัดแล้ว (ไม่เดา)
1. **ตาข่ายนิรภัยห้ามลบ:** `statsClassic` `allClassic` ใน `13-views` เป็นเส้นทางสำรองเมื่อกล่อง React ล้มหรือไม่มีข้อมูล ลบแล้วผู้ใช้เจอหน้าว่างแทนหน้าสถิติ ต้องย้ายเข้ากล่องพร้อมพิสูจน์ฉากว่าง ไม่ใช่ลบ
2. **ฉากภาพที่ยังขาด:** ไม่มีฉาก "สถิติว่าง" (ผู้ใช้ไม่มีกิจวัตร) และไม่มีฉากหน้า AI ที่ผูกกับ `16` `17` `18` ต้องเพิ่มฉากและภาพอ้างอิงจากเดโมของ Master ก่อนย้ายไฟล์เหล่านั้น
3. **ชั้น boot:** `index.html` โหลด `js/m/*.js` 27 ไฟล์แบบ `type=module` แยกกัน และ `window` เป็นสัญญาของชั้น boot (BOOT 37 จุดที่ F3 จัดว่าถอดไม่ได้) บางชื่ออาจต้องคง `window` ถึงปลาย F6 ต้องให้ Master ตัดสินว่ายอมรับหรือไม่ก่อนถึงชั้น 0 และ 13
4. **กล่อง React ไม่แตะ `window.UI/ST/S`:** [วัด: grepcount window.UI /tmp/evarel-repo/app/pages/*/*.jsx => 0] (ตรวจ `window.ST` `window.S` ด้วยมือแล้ว 0 เช่นกัน) ข้อมูลเข้าผ่านถาดเท่านั้น ดังนั้นย้าย `m/` เข้ากล่องแปลว่าต้องสร้างทางส่งข้อมูลใหม่ ไม่ใช่ย้ายตรงๆ

## เกณฑ์ "m ว่าง" ที่ตรวจด้วยเครื่อง (เสนอ ยังไม่ได้สร้างตัวตรวจ)
`find app/src/m -name '*.ts' ! -name '*.d.ts' | wc -l` ต้องเป็น 0 และ `index.html` ไม่อ้าง `js/m/` เหลือ และประตูภาพ 30/30 และ CI ผ่าน การสร้างตัวตรวจแบบอ่านอย่างเดียวที่รายงาน "เหลือกี่ไฟล์ กี่ชั้น" ควรทำก่อนย้ายไฟล์ถัดไป เพื่อให้ความคืบหน้าวัดได้โดยไม่ต้องอาศัยความจำ
